# PR / Commit / Repo — No Tool Attribution

This skill is the **workflow trigger** for the canonical policy in
`.cursor/rules/no-tool-attribution.mdc`. The rule is always-applied; this
skill makes sure the validation steps run at the moment you create or edit
PR/commit text.

The rule owns the canonical forbidden list and validation commands — do not
duplicate them here. If a phrase needs to be added/removed, edit the rule.

## When This Skill Activates

Trigger phrases (any of):

- "create a PR" / "open a PR" / "make a PR"
- "PR title" / "PR description" / "PR body"
- "edit the PR"
- "review this PR text"
- Implicit: any time you are about to call `gh pr create`, `gh pr edit`, or
  `git commit`

## Workflow

### Step 1 — Draft

Write the PR title, PR body, or commit message focused on product, behaviour,
and code changes.

### Step 2 — Self-check Against the Rule

Run the forbidden-phrase scan from `.cursor/rules/no-tool-attribution.mdc`
against the final text. The rule lists the exact phrases (Cursor, "Generated
by", `🤖`, AI/LLM attribution, etc.).

### Step 3 — Fix Violations Before Submitting

If anything matches, rewrite the offending lines. Do not submit until the
text is clean.

### Step 4 — Create / Edit Using Footer-Safe Paths

Prefer these creation paths because they preserve the exact authored content
and do not append tool footers:

```bash
gh pr create --title "Short title" --body "$(cat <<'EOF'
## Summary
- bullet 1
- bullet 2

## Test plan
- [ ] step 1
EOF
)"
```

Or, for commits, the HEREDOC form documented in the `git-commit` skill.

### Step 5 — Post-creation Validation (PRs)

Before sharing the PR URL with the user, hard-check the live body:

```bash
gh pr view <number-or-url> --json title,body \
  | grep -iE "cursor|generated by|co-authored-by.*bot|🤖|made with|created with|claude|gpt|copilot|ai assistant" \
  && echo "POLICY VIOLATION — fix before reporting" \
  || echo "OK"
```

If "POLICY VIOLATION" appears, edit the PR (or offending commit) and re-run
the validation. Only then share the URL.

### Step 6 — Post-creation Validation (Commits)

Right after `git commit`, scan the new commit:

```bash
git log -1 --format="%s%n%n%b" \
  | grep -iE "cursor|generated by|co-authored-by.*bot|🤖|made with|created with|claude|gpt|copilot|ai assistant" \
  && echo "POLICY VIOLATION — amend before pushing" \
  || echo "OK"
```

If a violation is found and the commit has **not** been pushed, amend it
(only when allowed by your own commit-safety rules) and re-check. If it has
been pushed, fix it immediately following the failure-mode section of the
rule.
